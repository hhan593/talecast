# 工程化复盘：审查-分支-PR-发版一轮（2026-11-17）

背景：v0.1.0 发布后，按五阶段流程（审查简化 → 架构评估 → 分支修复 PR → 发版 → 复盘）完整走了一遍。本轮 6 路评审产出 40+ 项发现，9 个 PR 修复 9 项结构/效率/测试问题，最终 v0.1.1。

## 问题与根因

### 1. 模板依赖是一次性吞下的隐形包袱（P0）
**现象**：6 个零 import 的模板依赖（@expo/ui、expo-glass-effect 等）与 13 个零引用模板图片存活了整个 P0-P4。
**根因**：`create-expo-app` 一次性铺开全部模板内容，而"分层骨架"的 P0 验收只检查了新写的代码，没检查"带来的东西"。
**经验**：脚手架落库后应立刻做一轮"引用清点"（每个依赖/资产 grep 消费者），未用的当场删。本轮已建立此习惯（见 findings R 系列）。

### 2. 覆盖叙述注释会腐烂，且比没有更糟
**现象**：`protocol.ts` 注释引用不存在的 `gec.test.ts/frames.test.ts`；`fakes.ts` 的注释声称与实现不符的级联语义。
**根因**：注释在描述"当时的计划状态"而非"现在的行为"。
**经验**：注释只保留三类——外部约束、API 契约、spec 链接；任务历史进 git log / docs/lessons。已把"services 不 import adapters"的约束**编码为 architecture.test 规则**（注释说不清的规则用测试钉住）。

### 3. 假信心测试靠变异测试才能揪出来
**现象**：`assistant.test` 断言 `version > 1`，但删除被测行为（流式持久化）后依然绿（结尾持久化兜底使 version=2）；`playback.test` 的 fireProgress 被 1500ms 节流吞掉，断言从未生效。
**根因**：断言的阈值/时机与实现细节耦合——"看起来在测"不等于"能失败"。
**经验**：对关键回归断言做一次**变异验证**（手工破坏被测行为，看测试是否变红）；阈值取"刚好能捕获目标回归"的值（version>2 而非 >1）；时序敏感断言用假时钟越过节流窗。

### 4. patch 脚本的静默失败两次差点污染 main
**现象**：批量文本替换脚本里两次 replace 未命中但没断言，导致坏 import 推上 main、构建断裂。
**根因**：`str.replace` 天然不报错；批量修改缺少逐项验证。
**经验**：所有脚本化修改必须 `assert old in s`（本轮后半段已全部断言化）；推 main 前必须 `pnpm typecheck`——这次正是它拦住了第二次事故。

### 5. 并发上限下的评审降级路径
**现象**：6 路并行评审有 3 路被 "user concurrency limit exceeded" 拒绝，重试仍失败。
**经验**：按 ce-simplify-code 的降级规则 inline 执行同一人设并披露替代；结果质量与子代理等价（发现项互补）。

### 6. 工具链硬版本要求要写进 README 而不是口头记
**现象**：iOS 构建被 Swift 6.2 工具链阻断（Xcode 16.3 vs 需要 26+），问题在两个会话间重复出现。
**经验**：环境类阻断（SDK 路径、NODE_PATH、Xcode 版本）写进 README 构建一节——本轮已沉淀。

## 可复用的经验清单

1. **先计划后编码 + PR 流程**：本轮 9 个 PR 全部一次合并通过，因为问题清单在动手前已分解到模块级。
2. **架构守卫测试化**：依赖方向规则写进 architecture.test 后，"是否合规"从人工判断变成 CI 断言（本轮新增第 3 条规则）。
3. **评审即清单**：六个正交视角（复用/质量/效率/结构/测试价值/注释）比单一"代码 review"覆盖面宽得多；每次全库审查都可复用此分法。
4. **内容寻址存储的缓存是免费的**：键不可变 → memo 无失效问题（readDecodedText memo 化零风险）。
5. **降级路径要披露**：并行评审撞上限时 inline 替代并明说，比默默少跑几路诚实。
