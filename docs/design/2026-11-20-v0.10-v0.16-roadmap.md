### v0.16.0 — 统一代码审查与修复（流程版）
1. **审查**：6 视角子代理评审（复用/质量/效率/结构/测试价值/注释；并发限制：**同时最多 2 个子代理**）+ 架构守卫全跑
2. **issue**：确认属实的发现逐条建 GitHub issue（标签 severity + 所在阶段版本）；误报关闭并注明理由
3. **修复**：每条 issue 一支修复分支（`fix/issue-<n>`）；**同时最多 2 个开放分支/PR**（串行合并）
4. **合并**：PR 逐个 review → merge → 删远程与本地分支 → 关闭 issue
5. **发版**：全部 issue 关闭后 bump v0.16.0 → tag → CI APK → Release notes

## 2. 并发与流程约束（贯穿全程）

- 子代理审查：最多 2 并行；修复分支：最多 2 开放（避免 CI 抢跑与冲突）
- CI 加 `concurrency` 组：同分支新推送取消旧构建
- 每阶段门禁不变：tsc 0 + 全量测试绿 + 架构守卫绿，才允许 commit/tag
- 分支纪律保持：main 单主干，修复走 PR 合并即删

## 3. Spike 决策点（带 go/no-go）

## 4. 交付节奏

每阶段：实现 → 门禁 → commit（feat(vX.Y.Z)）→ tag → CI 构建 APK → Release notes → 下一阶段。最终审查修复完成后统一收尾发 v0.16.0。
