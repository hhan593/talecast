# v0.9.0 对话式多语音 TTS（设计说明）

> 日期：2026-11-20
> 目标：旁白用旁白音色，角色台词用该角色绑定的音色——听小说的"有声剧化"体验。

## 1. 方案定位

**确定性启发式归属（v1）**，不走 LLM 逐段归属：
- 引号台词检测（「」『』“”\ " 四种配对，未闭合视作旁白）
- 说话人归属：在台词所在段落的**引号外文本**中查找已确认角色/别名（最长匹配优先），
  命中 → 该角色绑定的音色；未命中 → 旁白音色
- 全部规则落在 domain 纯函数（可测、可复现、零请求零成本）

LLM 归属（段落级"这句话是谁说的"）为后续增强位，接口已按 voiceKey 抽象留出。

## 2. 领域模型

### domain/dialogue.ts（新）
- `planVoiceSpans(chapterText, candidates)`：逐段扫描 → 引号区/旁白区 spans，
  **拼接覆盖全书（与 chapters/reader 同一套不变量）**；同段所有引号区共用一次归属
- `DialogueCandidate { key, names[] }`：key=characterId，names=角色名+别名
- `DIALOGUE_VERSION`：归属规则版本，参与 input_hash（规则升级 → 旧任务失效）

### domain/jobs.ts 扩展
- `buildVoiceSegmentPlan(chapterText, spans, segmentForTts)`：voice span 内部再走
  现有 TTS 分段器（句切 + 1200 上限），全局重排 ordinal
- `GenerationJobInput.voicePlanJson?`（可选）：参与 input_hash 的**多声计划指纹**
  （`{version, voices:[{key,voiceId,params,revision}…]}`，只含本段计划实际用到的音色）。
  **缺省（单声）不进哈希 → 既有任务/缓存哈希完全不变**；对话分声开关、任一相关绑定
  revision 变化都会产生新任务

### 段记录（迁移 v7）
`generation_segments` 新增 `voice_id TEXT` / `provider_params_json TEXT`（可空）：
- 旧任务段为 null → 合成回落 `job.voice_id`（重试兼容）
- text_hash 本就含 voice+params → 同文本不同音色天然不同缓存键，试听/重试零冲突

## 3. 服务编排（services/generation）

```
startGeneration:
  旁白绑定（必需，语义不变）
  dialogueEnabled = settings[`dialogue-voices:<projectId>`] !== 'off'   // 默认开
  ├─ 关：buildSegmentPlan（单声，路径与哈希与 v0.8 完全一致）
  └─ 开：characters × bindings → candidates
         planVoiceSpans → buildVoiceSegmentPlan
         每段按 voiceKey 解析 voice/params → computeSegmentTextHash
         voicePlanJson = 指纹(实际用到的 voice 条目)
runJobSegments: synthesize({ text, voiceId: segment.voiceId ?? job.voiceId })
```

- 无角色绑定时对话分声自动退化为单声（spans 全旁白），行为与成本不变
- 播放/导出零改动：队列与 MP3 拼接本就以段为单位，音色差异只体现在音频内容
- 预生成（v0.8.0 pregenNextChapter）自动继承对话分声

## 4. UI

- 工作台目录页新增 **"对话分声：开/关"** 开关（按书持久化）
- 角色中心提示语：给角色绑定音色后，开启对话分声即生效

## 5. 测试

- domain/dialogue：四种引号配对、未闭合忽略、归属（别名最长匹配/未命中旁白）、覆盖不变量、同段多引号共用归属
- domain/jobs：voice plan 分段（ordinal 连续、上限约束、span 内句切）
- services/generation：多声生成段携带不同 voiceId、text_hash 按音色区分、
  开关关→单声哈希不变、绑定变更→input_hash 变化、重试回落段级音色

## 6. 已知取舍

- 引号跨段（多段独白）v1 不合并：第二段起的引号按旁白处理——中文小说多段独白常带引号重复，影响有限
- 别名子串匹配可能误归属（如角色名恰为另一词的一部分）：最长匹配 + 段落级归属已压制大半；确认角色的别名人工可改
- 引号内出现人名（"李明，你来啦"）不会归属为李明——只扫引号外文本，避免称呼误判为说话人
