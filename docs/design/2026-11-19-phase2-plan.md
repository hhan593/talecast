# 计划书：二期阅读体验升级（仿真卷页 / 覆盖动画 / 横屏双栏 / EPUB / MOBI / 在线书源）

文档状态：已批准执行（用户指示）
日期：2026-11-19
前置：v0.3.0 已合并（R2 分页阅读器 + R3 书签搜索，docs/design/2026-11-19-manual-reading-plan.md）
发版映射：**v0.4.0 = 翻页动画 + 横屏双栏**；**v0.5.0 = 格式与书源**

## 1. 覆盖动画（v0.4.0）

PagerView 的平移过渡升级为"覆盖式"：当前页静止，下一页从右侧滑入覆盖（iOS 风格）。

- 实现：pager-view 的 `onPageScroll`（position + offset）→ RN Animated 插值——
  每页绝对定位叠放，按 offset 平移 + 阴影渐变；无新依赖（RN Animated）。
- 翻页模式设置：`settings` 表 key `page-turn-style`（slide / cover），阅读器按设置渲染。
- 验收：滑动跟手、松手回弹/落页与 pager-view 状态一致；两种模式切换即时生效。

## 2. 仿真卷页（v0.4.0，技术风险最高）

真卷页的主流实现路径：**react-native-skia 着色器**（Flutter 社区有成熟 page-curl shader，
RN Skia 可移植同款思路：卷曲几何 + 双面内容 + 阴影，全部在 shader 内计算）。

- 新依赖：`@shopify/react-native-skia`（大依赖，PR 说明理由：真卷页无纯 JS 可行方案）。
- 实现：Skia Canvas 叠在 pager-view 上，卷页进行中用 shader 渲染当前页/下一页
  （页面纹理用 `makeImageSnapshot` 截屏传入——iOS/Android 可用），卷页结束回到原生 pager。
- 交互：仅平移手势触发卷页动画；翻页模式设置新增 `curl`。
- 风险与降级：`makeImageSnapshot` 在低端机可能掉帧——设置页提供"关闭仿真卷页"开关；
  shader 移植失败则后置（不阻塞 v0.4.0，作为 v0.4.x 补充）。
- 验收：滑动跟手、卷曲角度随 offset 连续变化、阴影正确、无闪烁。

## 3. 横屏双栏（v0.4.0）

横屏时一屏显示两页（对页布局）。

- 分页：metrics 扩展 `columns`（1=竖屏单栏，2=横屏双栏）；
  每页内容不变，PagerView 一个滑动单位 = 一个"对页"（左右两页并排）。
- 实现：横屏时 `paginateText` 按双栏行数切页（每屏页数减半），渲染层并排两页。
- 与分页精度取舍一致：双栏切分同按字符偏移，不丢字。
- 验收：横屏下对页左右排列正确、翻页连续（上一屏末页 = 下一屏首页）；竖屏不受影响。

## 4. EPUB 导入（v0.5.0）

- 新依赖：`jszip`（EPUB = ZIP）、`fast-xml-parser`（OPF/TOC 解析）——PR 说明。
- 流程：选择 .epub → 解压 → META-INF/container.xml → OPF spine 顺序 →
  提取每章 XHTML → 去标签转纯文本（保留章节标题）→ 生成 sources + chapters（走现有导入管线）。
- 章节切分：EPUB 自带 spine/toc 结构，不再走正则分章候选——直接按 spine 建章节（title 取 toc）。
- 编码：EPUB 内 XHTML 为 UTF-8，天然满足首版 UTF-8 约束。
- 验收：样例 EPUB 导入后章节/阅读/分页/搜索全链路可用；损坏 EPUB 给出明确错误。

## 5. MOBI 导入（后置 v0.5.x）

**2026-11-18 执行评估**：npm 唯一候选 `mobi@0.0.1` 年久失修、API 未经验证，盲接入的破坏风险大于价值（计划书本节自评"风险中"）。按 §2 同款风险条款后置：

- 后置理由：唯一依赖候选不可靠；EPUB（结构化）与 TXT（通用兜底）已覆盖绝大多数存量书籍
- 恢复条件：出现可信的 PalmDOC JS 解包实现，或确认设备端 libmobi 原生方案
- 用户兜底：Calibre 等工具转 EPUB/TXT 后导入（首版导入文案已提示）

## 6. 在线书源（v0.5.0，分两阶段）

- **阶段一（本计划内）**：URL TXT 导入——设置/书架提供"从 URL 导入"，
  fetch 文本（UTF-8 校验沿用现有导入管线），纯下载不含书源规则。
- **阶段二（独立大版本后置）**：Legado 兼容书源规则引擎（搜索/发现/目录/正文 JSON 规则）。
  规模与法律边界（版权、站点 robots）需要单独评估——本期只做规则引擎的**数据模型与
  规则解析骨架**（`domain/source-rules.ts`：书源 JSON → 规则解析器，不含执行调度），
  完整引擎后置。
- 验收（阶段一）：URL 导入 TXT 后全链路可用；非文本/超限 URL 给出明确错误。
